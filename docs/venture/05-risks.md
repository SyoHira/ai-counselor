# 05. リスクと回避

---

## 1. データの取得方法（最重要・実装前に確定させる）

**AIの回答は、必ず各社の公式APIから取る。**
画面の自動操作や、規約で許可されていない自動アクセスはしない。理由は3つ。

1. 事業の根幹が規約違反の上に載ると、いつ止まってもおかしくない
2. 顧客（コンプライアンスが重い業界）に説明できない
3. 公式APIならリクエスト単位で費用が確定し、経費として説明できる

公式APIが無いサービスは、**対象から外すか、頻度を落とした手動サンプリングに留める**。
「全部のAIを見ています」と言うために規約を踏むのは、この事業では最も割に合わない。

**行政の公開データ**も同じ。提供形式と利用条件を一次情報で確認してから使う。
再配布の可否、出典表記の要件、機械的取得の可否は、着手前に必ず読む。

---

## 2. 自分の発信が規制に触れないようにする

この事業は健康食品の情報を扱うが、**自分は商品を売らない**ので広告規制の直接の対象にはなりにくい。
ただし書き方次第で踏む。

| やる | やらない |
|---|---|
| 「AIはこう説明した」と、観測結果として書く | 「この成分は効く／効かない」と自分の判断として書く |
| 「この表現に対して、過去にこういう処分の公表があった」 | 「この表現は違法です」と断定する |
| 出典と観測日を必ず添える | 出典なしで数字だけ出す |
| 事実を淡々と並べる | 特定企業を論評・批判する |

**判断を売らないことが、法的な安全と中立の信用を同時に作る。**
判断が欲しい顧客には「その判断は薬事の専門家に」と繋ぐ。ここは商売にしない。

---

## 3. 特定企業のネガティブ情報の扱い

措置命令の公表や届出撤回は、企業にとって不利な事実。扱いを間違えると業界から締め出される。

- **公表されている一次情報のみ**を、出典付きで記録する
- 推測・伝聞・匿名の情報は載せない
- 論評しない。並べるだけ
- 訂正の申し出には即応し、訂正履歴も残す

**中立の記録者という立場を守り続けることが、そのまま情報が集まる理由になる。**

---

## 4. 技術的なリスク

| リスク | 影響 | 対策 |
|---|---|---|
| AIのAPI仕様・料金・提供モデルが変わる | 観測が止まる／コスト増 | モデルを固定せず、複数を並列で見る。**モデルが変わったこと自体も観測対象として記録する** |
| 回答の揺らぎを「変化」と誤判定する | 誤アラート → 信用を失う | 1問3回試行。3回とも変わったときだけ変化と判定（02） |
| 保存していない項目が後から必要になる | 遡れない | **生の回答を全文保存する。迷ったら残す** |
| 週次実行が静かに失敗している | データが欠ける | 実行結果の自己監視。失敗したら自分に通知が来るようにする |

**4つ目が一番怖い。** 誰も見ていない週次バッチは、止まっても数週間気づかない。
この事業でそれは資産の欠損そのものなので、監視の監視を最初から入れる。

---

## 5. 事業としての壊れ方

| 壊れ方 | 対策 |
|---|---|
| 検索やAI経由の流入が経路ごと消える | 週報のメールリストを最優先で積む |
| 顧客がメーカー数社に偏り、1社抜けると崩れる | 代理店・コンサル・商社にも売り、業種を分散する |
| 自分が動けなくなって観測が止まる | 全部自動。手作業は週30分の編集だけに留める |
| 中立性を失う | サプリの販売・アフィリエイト・メーカーからの成功報酬を受けない（01） |

---

## 6. 未確認事項（着手前に必ず自分で確認する）

以下は本ドキュメントでは前提として書いたが、**一次情報での確認が必要**。
ここを確認せずに実装を始めない。

- 各行政データベースの提供形式・利用条件・機械的取得と再配布の可否
- 各AIサービスの利用規約における、回答の記録・比較・第三者への提供の扱い
- 価格・配合量データの取得元と、その利用条件
- 自分の発信が景品表示法・薬機法の観点で問題ないか（**業務として本格化する前に、薬事に詳しい専門家に一度見せる**）

本ドキュメントは事業判断の整理であり、法的助言ではない。
