# 02. パイプライン設計 — 毎週何を取るか

事業の本体はここ。**これが自動で回っている限り、資産は勝手に増える。**

---

## 観測対象

### 軸1：制度（行政の公開情報）

| 取るもの | 更新頻度 | 差分の意味 |
|---|---|---|
| 機能性表示食品の届出情報（新規・変更・撤回） | 随時 | 撤回は事業リスクの直撃。**通知が来ないので誰も気づかない** |
| 景品表示法の措置命令・課徴金の公表 | 随時 | どの表現がアウトになったかの実例 |
| 健康被害の報告・注意喚起 | 随時 | 成分の扱いが変わる前兆 |
| 成分の分類・規制ステータスの変更 | 随時 | 販売可否そのものが変わる |

※ 各データソースの正確な名称・提供形式・利用条件は実装前に一次情報で確認する（05参照）。

### 軸2：AIの回答

| 項目 | 設計 |
|---|---|
| 対象モデル | 公式APIが提供されている主要モデル 3〜4種 |
| 質問セット | 成分100種 × 質問5型 = 500問 |
| 質問5型 | ①これは何か ②効果はあるか ③安全か・副作用は ④どの製品が良いか ⑤誰が飲むべきでないか |
| 試行回数 | **1問につき3回**（回答は毎回揺れるため、1回では変化と揺らぎを区別できない） |
| 記録するもの | 全文、言及された成分名・ブランド名、肯定/中立/否定の傾向、免責の有無 |

**週あたり 500問 × 3回 × 3モデル = 4,500リクエスト。** 一人でも自動なら回る規模。

### 軸3：市場

| 取るもの | 差分の意味 |
|---|---|
| 主要成分ごとの商品価格 | 値崩れ・値上げの検知 |
| 配合量 | **静かな減量**（価格据え置きで量を減らす）の検知 |
| 新製品・販売終了 | 参入と撤退 |

---

## 差分の出し方

現状のスナップショットは商品にならない。**変化だけを抜くのが商品。**

```
今週のスナップショット  ─┐
                        ├→  比較  →  変化があった項目だけ  →  重要度で仕分け
先週のスナップショット  ─┘
```

重要度の仕分け:

| 段階 | 例 | 出す先 |
|---|---|---|
| 緊急 | 届出撤回、健康被害の公表、AIが安全性の評価を反転させた | 有料顧客へ即時アラート |
| 注目 | AIの説明の主要部分が変わった、措置命令が出た | 週報の頭 |
| 記録 | 表現の微修正、価格の小幅な変動 | ログに残すだけ |

**AIの回答の揺らぎと、本当の変化を区別する**のがここの技術的な肝。
3回試行のうち何回変わったかで判定する。1回だけの変化はノイズ、3回とも変わったら実際の変化。

## 技術構成

| 層 | 中身 | 理由 |
|---|---|---|
| 実行 | 週次のスケジュール実行（サーバーレス or 常駐1台） | 週1回なので常時稼働は不要。コストを抑える |
| 取得 | 各AIの**公式API**、行政の公開データ、価格情報 | 規約上グレーな取得はしない（05参照） |
| 保存 | 生の回答を全文そのまま保存（後から分析軸を変えられる） | **捨てたデータは二度と取れない。迷ったら全部残す** |
| 比較 | 週次スナップショット同士の差分 | |
| 出力 | 静的サイト（無料層）、メール（週報）、通知（有料アラート） | |

**設計上の一点だけ譲らないこと：生データを全部残す。**
今は使わない項目でも、1年後に「あの時どうだったか」を聞かれたときに答えられるかどうかが、この事業の価値そのもの。
