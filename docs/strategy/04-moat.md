# 04. 堀の作り方 — 辞書を資産として運用する

「揺るがない」の実装は、精神論ではなく**資産の構造**で決まる。
何が真似されうるか、何が時間でしか買えないかを分けて、後者に時間を寄せる。

---

## 1. 3層構造

### L1｜語彙資産 — 変換辞書

現物は `lib/systemPrompt.js` に既にある。

```
「脳の炎症」        → 「長い間の疲れが身体に溜まっている状態」
「愛着障害」        → 「幼い頃の経験が、今の人間関係のクセを作っている」
「報酬回路の炎症」  → 「楽しいと感じる力が一時的に弱っている状態」
```

- 模倣コスト: **中**。出力を読めば推測できる。単体では堀にならない。
- だからこそ **基礎部分は無償公開して標準を取りに行く**（後述）。

### L2｜応答パターン資産 — 効いた返し方の型と eval

- 実際の相談で「刺さった返し」「傷つけた返し」の記録。
- これを eval ケースに変換し、モデル更新のたびに回帰テストする。
- 模倣コスト: **高**。相談ログを持たない人には作れない。**①のセッションが原材料。**

### L3｜関係性資産 — 継続ユーザー・声・場

- `components/CommunityInsights.jsx` に既にUIがある（現状4件）。ここは飾りではなく資産の置き場。
- 有料リスト、継続ユーザー、実名の証言。
- 模倣コスト: **極めて高い**。金では買えず、時間でしか積めない。

---

## 2. 「①②の経験を③に変換する」の実装

参照元の一般論を、機構として固定する。**やる気に依存させない。**

```
セッション／受託案件
   ↓ 毎回、必ず記録する
「言ってはいけなかった言葉」「刺さった言い換え」「相手が黙った瞬間」
   ↓ 週1回のレビュー（固定の時間枠）
L1辞書に追記（v0.1 → v0.2 → ...）／ L2 eval にケース追加
   ↓ 四半期ごと
Andon Lexicon の新バージョンとしてリリース（既存購入者へ更新配布）
```

この機構があると:
- 案件をこなすほど③の商品が厚くなる（＝労働が資産に変換される）
- 更新配布があるため Lexicon をサブスク化できる（買い切りより継続収益）
- 追いつこうとする競合は、**過去3年分の事故事例を持っていない**ため常に遅れる

---

## 3. OSS＋有料の切り分け（標準を取る戦略）

L1を全部隠すのは間違い。隠しても真似され、しかも広まらない。
**基礎辞書を公開してデファクトを取り、周辺で稼ぐ。**

| 公開（無償） | 有料 |
|---|---|
| 基礎変換辞書（一般語彙 100語程度） | 領域特化辞書（メンタル／サプリ／恋愛／HR） |
| 禁止語リストの原則 | 事故事例つきの禁止語データベース |
| 設計思想のドキュメント | eval ケース集と自動回帰テスト |
| — | 危機対応プロトコル（05） |
| — | 四半期更新とモデル追随の保証 |
| — | 導入監修・カスタム辞書構築 |

公開で得るもの: 引用・被リンク・LLMへの取り込み・「Andon Lexicon 準拠」という言い回しの流通。
有料で得るもの: 責任を引き受ける部分（事故を防ぐ保証）。**責任は複製できないので、そこが最終的な堀になる。**

---

## 4. 複利になっているかの点検

四半期ごとに、この4問に答える。全部Noなら、その3ヶ月は労働しかしていない。

1. 辞書の語数は増えたか（v番号は上がったか）
2. eval のケース数は増えたか
3. 有料リストの人数と継続率は上がったか
4. 「作ったものが、自分が寝ている間に売れた」金額は増えたか

---

## 5. 参入障壁になる「面倒なこと」

競合が嫌がることを、こちらが引き受けるほど堀は深くなる。

| 面倒なこと | なぜ障壁になるか |
|---|---|
| 薬機法・医療広告ガイドラインの遵守（05） | 大半の個人発信者は無視する。事業者は無視できない → 事業者向けの独占 |
| 危機対応（希死念慮）フローの設計・運用 | 責任が重く誰もやりたがらない。だが必須。やった者が総取り |
| モデル更新のたびの回帰テスト | 地味で継続コストが高い。継続できる人が極端に少ない |
| 変換辞書の日本語としての品質管理 | 機械翻訳的な言い換えでは成立しない。手作業の蓄積が要る |

これらは「参入障壁は技術ではなく、引き受ける責任の量で決まる」という原則の具体形。
