# 04. 売り始める前に潰すこと

> 法的な最終判断は弁護士に。ただし「弁護士に見せられる状態」を先に作っておくと確認は速く安く済む。

---

## 最優先：「死にたい」と言われたときの対応が無い

`lib/systemPrompt.js` には、希死念慮・自傷・虐待の開示への方針が**一切書かれていない**。

トピックには「虚無感」「自己価値」「燃え尽き」が並んでいる。
**この状態のユーザーが危機的な発言をする確率は低くない。**

対応がないまま支援者や企業に見せると、その場で商談が終わる。一度断られた相手には二度と売れない。
だから商売の順番としても、これが最初。

### 実装するもの

1. 検知（危険なキーワード＋文脈）と、通常フローからの分岐
2. 応答テンプレート — 否定せず、責めず、窓口を案内する言い方（**Andonが一番得意な領域**）
3. 公的窓口の案内（運用前に最新情報を確認する）
4. その分岐が壊れていないかを毎回テストする仕組み

### 反転

**この危機対応フローが、DBとテンプレの中で一番高く売れる部分になる。**
誰もやりたがらず、しかし事業者は必ず必要とする。面倒なことを引き受けた分がそのまま参入障壁になる。

---

## 薬機法：サプリの書き方

現状の `lib/systemPrompt.js`:

```
睡眠改善：グリシン（就寝前3g）、マグネシウム（就寝前200-400mg）
集中力：イチョウ葉エキス、ロディオラ
ストレス・疲労回復：アシュワガンダ、ビタミンB群
```

問題は**「効能の見出し」＋「具体的な用量」の組み合わせ**。医薬品的な効能を謳っていると解釈されうる。
「注意を添える」指示は緩和にはなるが免罪符にはならない。

### 直し方

1. 見出しを効能から状態の記述に変える（「睡眠改善」→「睡眠の話題で挙がりやすい成分」）
2. 用量の断定をやめ、一般に流通している目安の範囲として書く
3. 「診断」「治療」「予防」を想起させる語を禁止語リストに追加する
4. **サプリを売らない・アフィリエイトをやらない**（01の「やらないこと」）。
   収益源をサプリに置いた瞬間、規制上の立場も中立性も同時に失う

このチェックリスト自体を商品（テンプレ・DB）に同梱する。**法律込みの辞書**という売りになる。

---

## 診断機能を作らない

「あなたは◯◯の傾向があります」という判定機能を足すと、法規制の対象になる可能性が出る。
今の相談・情報提供の形なら問題になりにくい。**機能追加のときに必ずこの線を確認する。**

---

## 相談ログの扱い

相談内容は健康・精神状態に関する情報で、扱いが重い。
今はブラウザ内保存だが、**サーバーに貯める／学習に使うなら、同意の取り方を先に設計する。**
ここを雑にやると、資産のはずのログが負債に変わる。

---

## 事業としての壊れ方

| 壊れ方 | 対策 |
|---|---|
| SNSの規約変更で集客が消える | メールアドレスを最優先で集める（③-1） |
| AIが賢くなってアプリが不要になる | 売り物をアプリではなく辞書に置く（01） |
| 自分が動けなくなって全停止 | 辞書を外部化し、自分以外でも運用できる形にする |
| 相談を受けすぎて③を作る時間が消える | 月8本の上限を先に決める（02） |
