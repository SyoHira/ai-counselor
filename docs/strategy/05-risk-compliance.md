## P0｜危機対応が未実装（最優先・事業存続に関わる）

### 現状

`lib/systemPrompt.js` には、以下が**一切定義されていない**。

- 希死念慮・自傷の表明が来た場合の応答方針
- 虐待・DV・暴力被害の開示が来た場合の方針
- 専門機関・相談窓口へのエスカレーション
- 「AIが対応してはいけない」境界の明示

トピックには「虚無感」「自己価値」「燃え尽き」が並んでおり、
**この層のユーザーが危機的発言をする確率は低くない。** 対応がないまま運用するのは、
倫理的な問題であると同時に、**②③（事業者向け販売）が成立しなくなる致命的な欠格事由**でもある。
事業者は必ずここを見る。

### やること

1. 検知（キーワード＋文脈判定）と、通常フローからの分岐
2. 定型の応答テンプレート（否定せず、責めず、窓口を案内する言い方 ＝ まさに Andon の得意領域）
3. 公的窓口の提示（いのちの電話、こころの健康相談統一ダイヤル、#いのちSOS 等。運用前に最新情報を確認）
4. 該当セッションのログ方針と、開発者側のレビュー手順
5. eval ケース化（この分岐が壊れていないことを常時検証）

### 反転

**この危機対応プロトコル自体が、Andon Lexicon の最も高く売れる部分になる。**
誰もやりたがらず、しかし事業者は必須で必要とする。04の「面倒なことが障壁になる」の典型。

## P1｜薬機法・医療広告ガイドライン

### 現状のリスク箇所

`lib/systemPrompt.js` のサプリメント知識セクション:

```
睡眠改善：グリシン（就寝前3g）、マグネシウム（就寝前200-400mg）、L-テアニン（200mg）
集中力：イチョウ葉エキス、ロディオラ、L-テアニン
ストレス・疲労回復：アシュワガンダ、ビタミンB群、ビタミンD
```

問題になりうる構造:

| 論点 | リスク |
|---|---|
| 「睡眠改善」「集中力」という**効能効果の見出し**＋具体的用量の組合せ | 医薬品的な効能標榜と解釈されうる（薬機法68条・未承認医薬品等の広告禁止） |
| AIが個別状況に応じて用量を提示する | 個別の助言＝実質的な指導と見なされうる |
| 将来サプリのアフィリエイト／販売を行う場合 | 広告該当性が明確になり、規制が直撃する |

現行の「必ず注意を添える」指示は緩和にはなるが、免罪符にはならない。

### 対応方針

1. **効能の見出しを、状態の記述に置き換える**（「睡眠改善」→「睡眠について話題に上がりやすい成分」）
2. 用量の断定を避け、**一般に流通している目安の範囲**として記述し、出典の性質を明示
3. 「診断・治療・予防」を想起させる語を禁止語リストに追加（`systemPrompt.js` の禁止事項セクションを拡張）
4. **サプリ販売・アフィリエイトとの距離を戦略として維持する**（01「やらないこと」）。
   収益源をサプリに置いた瞬間、規制上の立場も、ブランドの中立性も同時に失う
5. 上記をチェックリスト化し、辞書の一部として商品に含める → **コンプライアンス込みの辞書**という差別化

### 医療機器該当性

「診断」「判定」「スコア化」を行う機能は、プログラム医療機器（SaMD）該当の検討対象になりうる。
**現状のMVPは相談・情報提供に留まっており該当しないと考えられるが、
「あなたは〇〇の傾向があります」型の判定機能を足す時点で線を越える。**
機能追加時は必ずこの観点を通す。01「やらないこと」に診断機能を入れているのはこのため。

## P2｜個人情報・データ

- 相談内容は要配慮個人情報に該当しうる（健康・精神状態）。
- 現状はセッションをブラウザ側に保存する構成だが、**サーバー保存／学習利用に踏み込む場合は、
  利用目的の明示と同意取得の設計が必須。**
- L2資産（相談ログからの学習）を作る際は、**匿名化と同意**を先に設計する。
  ここを雑にやると、資産のはずのログが負債になる。

## P3｜事業構造上のリスク

| リスク | 影響 | 対策 |
|---|---|---|
| プラットフォーム依存（SNS・note のアルゴリズム／規約変更） | 集客と収益が一夜で消える | **メールリストを最優先資産に置く**（02-③a） |
| LLM API の価格・仕様変更 | 原価とプロンプト挙動が変わる | 辞書をモデル非依存の形式（YAML）で保持。eval で追随を検知 |
| 汎用LLMの品質向上でチャットUIが陳腐化 | B2Cアプリの価値低下 | 主商品を辞書とAPIに置く。アプリはショーケース扱い（01） |
| 属人性（本人が動けなくなる） | 全停止 | 辞書とevalの外部化＝本人以外でも運用可能にする（03の検証項目） |
| 単価の下落圧力 | 労働の泥沼化 | ①の本数上限と値上げルールを事前に固定（02） |

## 実行順序の固定

**Phase 0（Day 1-14）の完了なしに、②③の販売を開始しない。**
理由は倫理だけではない。危機対応と薬機法対応が未整備の状態で事業者に売り込むと、
一度断られた相手には二度と売れないため。**最初の商談の前に、ここを終わらせておくことが最も安いリスクヘッジ。**
