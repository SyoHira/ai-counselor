# 06. 売り出しの準備：アカウント設計・プロフィール・図・SNS

文面と画像は `engine/n1engine/channels/` の `brand.py`（プロフィール）・`sns.py`（30日の計画）・`images.py`（図）から作る。

```
python -m n1engine.run brand --example brand.json     # 設定の見本。【要記入】を事実のとおりに埋める
python -m n1engine.run brand --config brand.json --out ../sales/brand
```

出力：`sales/brand/profiles.md`（プロフィール文と字数）・`sns-plan.md`（30日の投稿・note記事・計る数字・続ける線）・`img/`（PNG 21枚）。`sales/brand/` のうち md はテストで元と一致を確認している（直すときは元を直して作り直す）。

## 1. アカウントの役割

| 場所 | 役割 | 置くもの |
|---|---|---|
| ココナラ | **売る** | 出品（入口・標準・上級・伴走者向け）。購入前相談が入口。外部URL・メールアドレス・QRは書かない |
| note | **見せる** | 自分の実験の記録、方法の長い解説、公開データの分析。メンバーシップは受け皿 |
| X | **見つけてもらう** | 短い記録と図。固定ポストとプロフィールのリンクで note へ |
| Instagram | 後回し | 字数・画像比率の公式値を確認できていない。X と note で何が反応を得るかを測ってから |
| 自分のサイト | 実績と表示がそろってから | `run site`。特定商取引法の表示などの【要記入】を埋める |

名前（1人実験ノート）・アイコン（`n=1`）・色（深緑と青緑、グラフは青と橙）はすべて同じにする。どこから来ても同じ人と分かるようにするため。

## 2. プロフィールの方針

- 一言：「サプリに払い続ける根拠を、あなたの記録で確かめる」。入口の約束を1文にしたもの
- 最初の3行で「やること・やらないこと（成分は勧めない・働きは語らない）・差が見つからなくてもそのまま伝える」を言う。買い手が最初に持つ疑い（何かを売りつけられないか）に先に答える
- 資格・経歴は事実のとおりに書く。書かなければ【要記入】が残り、生成時に警告する。無い資格を匂わせない。無い場合は「医療の資格はありません。診断や指導はしません」と書く
- 実績：「まだありません。最初の10件はモニター価格」と書く。件数・評価・お客様の声は、得てから、根拠を残して書く
- 字数の上限は `brand.py` の `LIMITS` に出典の確認の程度つきで置いてある。公式の要約で確認できたもの（X の名前50・自己紹介160・ポスト280（全角は2）、Instagram 150）と、ブログ由来で公式未確認のもの（note の自己紹介140）、仮置きのもの（ココナラのプロフィール1000）を分けている

## 3. 売れる図の使い方

| 図 | 使う場所 | 言うこと |
|---|---|---|
| `thumb_entry`・`thumb_standard`・`thumb_premium`・`thumb_partner` | ココナラの出品サムネイル（1220×1240。ブログ由来で公式未確認。出品画面で実測する） | 各商品が何をするか |
| `fig_decision` | X・note・出品の2枚目 | 月々の支払い＋記録の結果＝判断の材料。この商品の中心 |
| `fig_compare`・`fig_power` | X・note | 検証の数字（偽データ。件数と条件を併記） |
| `fig_melatonin` | note | 公開データの分析（MITライセンス、出典を併記）。「はっきりしない」を隠さず出す |
| `card_*` | X の投稿に添える | 方法の説明（引きずり・折り返しの並び・見つからない≠無い・飲む時刻・成分の対象外・2成分・立場・次の3つ） |
| `x_header`・`note_header`・`icon` | プロフィールの画像 | 名前と一言 |

守ること：
- 図の数字は、リポジトリで確かめた値か、画像に「見本（架空の記録）」「説明用の例（架空）」と書いた例だけ。作った数字を実際の記録に見せない（テストで確認）
- 画像にURL・メールアドレス・QRを入れない（ココナラの禁止事項。テストで確認）
- 「効く」「改善」などの言葉を使わない（テストで確認）
- 書体は Google Fonts の Zen Kaku Gothic New。読み込めない環境では別の書体になる。利用条件は出品前に確かめる

## 4. 30日の SNS の計画

`sns-plan.md` に22本の投稿・note記事3本・計る数字・続ける線を置いた。

- 投稿の柱：検証の数字／方法の説明／公開データの分析／自分の実験の記録／立場（勧めない）
- 投稿は、このリポジトリで確かめた事実（`sns.py` 冒頭のF1〜F8）だけで書いている。成分の働き、「飲んだら〜になった」の体験談、No.1・満足度は書かない
- 【自分の記録】の投稿（3・10・17・21日目）は、自分が28日の実験をして得た実際の記録で埋めてから出す。作ったデータを自分の記録として出さない。埋まるまで生成時に警告する
- 投稿の時間帯が良いという根拠は確認できていない。測って決める

### 続ける・変えるの線

業界の平均値は確認できなかったので、自分で決めた値で判断する（`sns.py` の `DECISION_LINES`）。30日・60日・90日で、見つけてもらう（表示・プロフィール訪問）→ 読まれる（note）→ 相談が来る → 買われるの各段を数え、詰まった段を直す。

## 5. 守ること（広告・表示）

- 自分のアカウントでの自分のサービスの宣伝は、売り手が誰か分かる形で出す。第三者になりすまさない
- お客様に感想の投稿を頼まない。内容を指定すると事業者の表示になり、明示が必要になる。お客様の声は、実績ができてから、同意を得て、手を加えずに載せる
- 個人の感想の注記を付けても、効果の示唆なら判断は変わらない（消費者庁の留意事項）ので、体験談の形で効果を示唆しない
- 規制の整理と出品前の確認は [04-compliance.md](04-compliance.md)

## 6. 売り出しまでの順番

1. `run brand --example` で設定を作り、【要記入】を事実のとおりに埋める（資格・経歴・始めた理由）
2. 自分の28日の実験を始める（記録そのものが投稿とnote記事の材料になる。`run sheet` で記録用Excelを作る）
3. 出品前の確認（[sales/README.md](../sales/README.md) の「出品前に確かめること」、ココナラのヘルプ原文、運営への事前問い合わせ）
4. ココナラに入口と標準を出品（サムネイルは `img/thumb_*.png`）。note と X のアカウントを同じ名前・アイコンで作る
5. 30日の計画を始める。毎週、計る数字を数える
